# 更新通道、版本发布与代码签名

## 一、当前能力

- 桌面版版本号读取主程序 `package.json`，安装包名自动带版本号。
- 托盘菜单提供“检查更新”和“导入更新通道配置”。
- 更新清单使用 Ed25519 签名，安装包使用 SHA-256 校验。
- 只有 HTTPS 地址会被接受。
- 未配置更新通道时，系统不会联网检查更新。
- 更新安装包启动后使用标准安装程序覆盖程序文件，业务数据保留在用户数据目录。

## 二、发布方需要准备的固定资产

这部分不能由客户在每台电脑上手工修改，应一次配置、长期复用：

1. 一个稳定 HTTPS 域名或对象存储地址。
2. 一份 Ed25519 发布私钥。私钥只保存在发布电脑或 CI 密钥库。
3. 一份与私钥对应的公钥。公钥可以放入 `update-config.json`。
4. 一个固定更新清单地址，例如：

```text
https://download.example.com/yukang/update-manifest.json
```

5. 一个固定安装包目录，例如：

```text
https://download.example.com/yukang/YuKangClinic-Setup-5.1.1-x64.exe
```

## 三、生成 Ed25519 发布密钥

在发布管理电脑上执行：

```powershell
node -e "const c=require('crypto'),f=require('fs');const k=c.generateKeyPairSync('ed25519');f.writeFileSync('release-private.pem',k.privateKey.export({type:'pkcs8',format:'pem'}));f.writeFileSync('release-public.pem',k.publicKey.export({type:'spki',format:'pem'}))"
```

- `release-private.pem` 严禁进入 Git、安装包、客户包或公网仓库。
- `release-public.pem` 用于生成客户端配置，可以公开。
- 私钥丢失后不能继续证明新版本来源，必须重新下发配置。

## 四、生成签名更新清单

假设新安装包已构建：

```powershell
cd desktop
node scripts/sign-update.js `
  --installer "artifacts\YuKangClinic-Setup-5.1.1-x64.exe" `
  --version 5.1.1 `
  --download-url "https://download.example.com/yukang/YuKangClinic-Setup-5.1.1-x64.exe" `
  --manifest-url "https://download.example.com/yukang/update-manifest.json" `
  --private-key "D:\ReleaseSecrets\release-private.pem" `
  --notes "修复库存导出并优化更新稳定性" `
  --output-manifest "D:\ReleaseSecrets\update-manifest.json" `
  --output-config "D:\ReleaseSecrets\update-config.json"
```

生成的 `update-config.json` 示例：

```json
{
  "updater": {
    "channelUrl": "https://download.example.com/yukang/update-manifest.json",
    "publicKey": "-----BEGIN PUBLIC KEY-----\n...\n-----END PUBLIC KEY-----"
  }
}
```

将 EXE 和清单上传后，在客户机上导入配置：

1. 右键托盘图标。
2. 选择“导入更新通道配置”。
3. 选择发布方提供的 `update-config.json`。
4. 点击“检查更新”验证。

## 五、自动更新和控制面的区别

- 静态更新通道：一个公共 HTTPS 清单即可，适合单机客户统一升级。
- 云控制面更新：适合按客户、门店、版本分批灰度更新，但需要部署 `cloud_control_plane`、PostgreSQL、证书和 Edge 注册。通用安装包不能内置同一套 Edge Token，必须做首次激活或 provisioning。
- 当前桌面安装包已经包含静态更新检查；控制面代码保留为高级部署能力。

## 六、Authenticode 代码签名

正式推广前应购买受信任的 OV 或 EV Windows 代码签名证书。electron-builder 支持通过环境变量或证书文件签名，推荐做法：

```powershell
$env:CSC_LINK = 'D:\ReleaseSecrets\yukang-code-signing.pfx'
$env:CSC_KEY_PASSWORD = '证书密码'
npm run dist:win
```

构建后必须验证：

```powershell
Get-AuthenticodeSignature "artifacts\YuKangClinic-Setup-5.1.1-x64.exe" |
  Format-List Status,StatusMessage,SignerCertificate
```

只有 `Status` 为 `Valid` 才能进入正式客户交付目录。当前仓库不包含任何证书，因此本地测试构建会显示 `NotSigned`。

## 七、发布验收顺序

1. 更新版本号。
2. 构建完整知识库版本。
3. 运行离线资源和运行时校验。
4. 启动 EXE，检查托盘、端口、备份和二维码。
5. 使用代码签名证书签名。
6. 验证 Authenticode 时间戳。
7. 计算 SHA-256。
8. 生成并签名更新清单。
9. 上传安装包与清单。
10. 在干净 Windows 虚拟机中从旧版升级验证。
11. 归档发布说明、校验值和许可证。
