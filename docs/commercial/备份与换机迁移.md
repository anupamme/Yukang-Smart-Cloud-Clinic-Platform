# 备份、恢复与换机迁移

## 一、三种数据保护方式

| 方式 | 用途 | 是否可跨电脑 |
| --- | --- | --- |
| 自动 SQLite 快照 | 同一台 Windows 用户下误操作恢复 | 否 |
| 手动数据库快照 | 重大操作前留档 | 否 |
| 完整 JSON 导出 | 换机、重装、迁移和长期归档 | 是 |
| HTML 报表 | 给管理者查看或打印 | 只读，不可恢复 |

## 二、同一台电脑恢复

进入“设置 → 图形化备份与恢复”：

1. 点击“刷新”查看快照。
2. 点击“立即备份”保留当前状态。
3. 选择要恢复的快照。
4. 输入确认文字 `RESTORE`。
5. 系统会先创建 `pre-restore` 快照，再恢复数据库。
6. 恢复完成后重新登录并抽查患者、库存和收费数据。

## 三、换机迁移正确步骤

### 旧电脑

1. 停止接诊和收费操作。
2. 点击“立即备份”。
3. 点击“导出完整数据”，得到 JSON 文件。
4. 将 JSON 文件复制到外置盘或加密介质，不要放在公共网盘。
5. 记录当前系统版本、账号角色、门店名称和最近一次收费日期。

### 新电脑

1. 安装同一主版本或更高兼容版本的 EXE。
2. 先注册一个新账号。账号、密码和 Windows DPAPI 密钥不会从旧机直接复制。
3. 进入“设置 → 图形化备份与恢复”。
4. 点击“导入/换机恢复”，选择旧机导出的 JSON。
5. 输入确认文字 `IMPORT`。
6. 导入完成后刷新页面，核对患者数量、库存余额、收费汇总和最近处方。
7. 重新配置第三方 AI Key、打印机和局域网访问。
8. 立即新建一次快照，作为新机的恢复基线。

## 四、为什么不能直接复制 clinic_database

Windows 版会使用 DPAPI 保护设备密钥。该密钥与 Windows 用户绑定，复制到另一台电脑或另一个 Windows 账号后通常无法解密。直接复制数据库可能出现“数据文件存在但无法读取”的情况。

## 五、连锁门店怎么迁移

JSON 导出按当前登录用户和当前门店范围执行。连锁机构迁移时应：

1. 总店先导出总店数据。
2. 各分店分别登录并各导出一份。
3. 新环境重新建立组织和门店账号。
4. 按门店逐个导入。
5. 重新生成分店邀请码或重新绑定账号。

账号控制库、邀请码、机构关系和审计状态不应使用普通业务 JSON 代替专业迁移工具。正式连锁迁移应由发布方提供受控迁移流程。

## 六、备份保留规则

- 系统默认保留最近 60 份自动快照。
- 建议每周把一份 JSON 导出到离线介质。
- 建议每日夜间至少保留一份异地副本。
- 备份文件包含敏感患者资料，必须加密保存并限制访问。
- 恢复操作必须由负责人授权并在记录中留痕。
