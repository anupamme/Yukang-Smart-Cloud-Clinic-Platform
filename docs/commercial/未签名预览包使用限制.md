# 未签名预览包使用限制

适用状态：`internal-preview-unsigned`、`commercial-signed-pending-release-gates`

## 一、结论

当前交付包如果没有 `Valid` 状态的 Authenticode 签名，就 **不是可以直接售卖、公开推广或交付真实诊所长期使用的正式商业版**。

它可以用于：

- 开发人员内部安装验证。
- 客户演示和功能验收。
- 安装、卸载、端口、托盘、备份恢复等流程测试。
- 不包含真实患者数据的受控预生产环境。

它不可以用于：

- 在线上或线下公开销售、收费分发。
- 投放到网站、网盘、群聊、展会或第三方下载站。
- 让真实诊所录入真实患者资料后长期运行。
- 以内置统一云端 Token 的方式连接商业云控制面。

## 二、可能出现什么现象

未签名 EXE 在部分 Windows 电脑上会触发：

- “Windows 已保护你的电脑”。
- “未知发布者”。
- SmartScreen 阻止运行。
- 杀毒软件或企业终端管控软件告警。

这些现象不代表安装包一定含病毒，但会降低客户信任，也不适合作为正式商业交付体验。

## 三、发布方如何自查

在 PowerShell 中执行：

```powershell
Get-AuthenticodeSignature -LiteralPath '.\YuKangClinic-Setup-5.1.0-x64.exe' |
  Format-List Status, StatusMessage, SignerCertificate
```

正式对外包必须满足：

```text
Status = Valid
```

同时检查交付目录：

```text
发布信息\RELEASE_INFO.json
```

正式推广包必须满足：

```text
signature_status = Valid
release_channel = commercial-signed
promotion_ready = true
data_license_confirmed = true
clean_vm_verified = true
```

## 四、解除限制的条件

只有同时完成以下事项，构建脚本才应把 `promotion_ready` 标记为 `true`：

1. 使用受信任的 Windows 代码签名证书完成 Authenticode 签名和时间戳。
2. 确认药典数据及全部第三方内容的商业授权范围。
3. 在全新 Windows 10/11 x64 虚拟机完成安装、启动、升级、卸载和数据保留验收。
4. 补充正式客服入口、合同主体、隐私政策和所在地合规材料。
5. 完成真实部署边界的权限、限速、CSRF、审计和渗透测试复核。

构建时使用：

```powershell
.\tools\build-commercial-release.ps1 `
  -CertificatePath 'D:\release-secrets\yukang-codesign.pfx' `
  -DataLicenseConfirmed `
  -CleanVmVerified
```

任何一项未完成时，都不能用“正式版”“商业稳定版”“可大规模推广”描述该安装包。
